GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。これらの作業は自分のマシン上でリアルタイムに進むため、VS Code の Copilot Chat では各ツールの呼び出しとファイル編集を確認できます。差分をインラインで確認して変更ごとに承認または取り消し、エディターを離れずに追加のプロンプトで会話を誘導し、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントを誘導し、ハイ コントラスト モードに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装中です。作業中にデザイン チームから追加の依頼がありました。既定のテーマは暗すぎると感じる利用者向けに、ライト モードの切り替えも追加してほしいとのことです。新しい会話を最初から始める代わりに、既存のセッションを誘導して作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップが表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集はそれぞれ差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取り、編集、実行許可を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャットの上部にある **Files changed** の表示を開くと、セッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは処理を一時停止して **Allow** の確認を表示します。実行してよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントを誘導してライト モードを追加する

ハイ コントラスト モードができたら、同じ会話を続けてライト モードの切り替えも追加します。同じチャット セッションを使うため、エージェントは前の作業で触れたコンポーネント、採用したスタイル、設定したローカル ストレージのパターンを把握しています。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の変更を確認し、ライト モード用の追加を提案します。
3. ハイ コントラスト モードの場合と同様に、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. たとえば、エージェントが好みに合わない方法で切り替え UI をリファクタリングしようとした場合は、チャット入力欄の横にある **Stop** ボタンを使って停止し、説明を追加するプロンプトを送信します。

> [!TIP]
> 実行中のセッションを誘導すると、最初からやり直すより効率的です。追加のプロンプトで変更を依頼したり ("CSS を簡素化して、セレクターの重複ではなく CSS 変数を使用する")、進行方向を修正したり ("3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを追加する")、作業範囲を広げたり ("両方の切り替えにキーボード ショートカットも追加する") できます。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタム エージェントが指定したアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージへの保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視して誘導しました。ファイルの編集を確認して承認または取り消し、コンテキストを保ったまま追加のプロンプトで作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイルの編集を承認または取り消す。
- 追加のプロンプトで実行中のセッションを誘導する。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、この演習でローカルのカスタム エージェントが作成した変更をレビューします。
