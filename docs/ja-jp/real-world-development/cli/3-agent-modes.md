まずは小さな機能をプロジェクトに追加しました。より大きな変更には、さらにしっかりしたプロセスが必要です。GitHub Copilot CLI は組織で使われている既存の開発フローに沿って作業できるため、適切な方法で必要なものを構築できます。このレッスンから、Issue を使って新機能を作り、コードの正しさと機能の動作を確認してからプロジェクトにマージする、エージェントを使った一般的な開発プロセスを進めます。

> [!NOTE]
> この機能のワークフローでは、同じ会話とブランチを使い続けます。通常はファイルの種類ごとにブランチや PR を分けますが、ここでは重要な概念に集中するため、手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の新しい会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

機能の作業を続ける中で、リポジトリの命令を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して、QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のカタログが増えているため、訪問者がカテゴリや発行元でゲームを絞り込めるようにします。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コードを書く前に合意しておきたい詳細があります。Plan モードで決定事項を整理し、範囲を定めてから Autopilot に実装を任せます。

## 背景

AI コーディング エージェントを開発フローに取り入れても、基本的な開発手順は変わりません。むしろ、これまで以上に重要になります。多くの開発者は、次のような手順で作業します。

1. 必要な作業を説明する Issue を作成します。
2. 実装する内容の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で確認します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 実際の手順はチームや組織によって異なりますが、多くの場合、上記の流れを基本としています。

この標準的な方法に沿うことで、AI が生成したコードが要件を満たし、手書きのコードと同じレビューを経ていることを確認できます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと共同で作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが計画を作成します。プロジェクト ファイルの編集はできません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで計画を確認してから、Autopilot で実装します。

## Issue から始める

フィルタリングの作業を始める前に、Codespace とリポジトリの準備を確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続けてください。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) を会話のコンテキストに含められます。

## フィルタリング機能を計画する

計画を立てることで、機能の実装方法やタスクの進め方を、Copilot に任せる前に定義できます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替え、計画を作成するよう Copilot に依頼しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下のモード表示が **Plan** であることを確認します。
2. 直前の手順で追加した Issue の参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査し、最適な実装方法を判断して計画を作成します。

3. フィルタリングの動作について質問されたら、自分の希望に沿って回答します。唯一の正解はありません。
4. 計画ができたら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を確認します。
6. 決定事項と異なる部分があれば、修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたので、実装に進みます。Autopilot を使って Copilot に作業を任せましょう。

Autopilot を使うと、Copilot はタスクが完了したと判断するまで、問題の解決に向けて反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストールしたバージョンで同様の名前の選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画をレビューしてください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェックを完了と見なす前に環境の問題を解決します。

## 実装をレビューして検証する

他のコードと同様に、生成されたコードもマージ前にレビューする必要があります。コードを確認し、サイトを起動して問題がないことを確かめます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** や **Autopilot** が出ていないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを調べます。
3. 結果が Issue と計画時の決定事項に沿っていることを確認します。
4. コードをレビューしたら、<kbd>Esc</kbd> を押して差分表示を終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば修正を依頼します。

## 新機能を試す

コードの確認ができたら、実際に動作するかを確かめましょう。前と同じようにアプリを起動し、Codespaces から転送されたポートを使ってサイトを開きます。

1. 次のプロンプトで Copilot にアプリを起動してもらいます。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces にポート `4321` が使用可能と表示されたら、**Open in Browser** を選択します。
3. 計画で合意した条件に沿って、カテゴリ、発行元、および両方を組み合わせたフィルターを試します。
4. リセット時と結果がない場合の動作が Issue と決定事項に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

## まとめと次のステップ

会話モードを切り替えながら、機能を構築してレビューしました。このレッスンでは次のことを行いました。

- GitHub Issue から Copilot の新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。
